# 设计文档

## 前言

本文档为 2025 年毕昇杯编译大赛参赛队伍 **移进规约都队** 的编译器设计总览。本编译器面向官方 SysY 语言，以自研 IR 为中间表示，以 **RISC-V** 为最终目标体系结构。

## 1. 总体架构

编译器采用经典三段式流水线，各阶段通过自研 IR / RISC-V MIR 解耦：

```
SysY 源码
  → [前端] ANTLR4 Parse Tree → AST → 语义分析
  → [中端] IRBuilder → 自研 IR → PassManager（多级优化）
  → [后端] 指令选择 → 窥孔 / CSE / LICM → 指令调度
         → 图着色寄存器分配 → 窥孔 → 栈偏移重算 → 汇编发射
  → RISC-V 汇编
```

**工程目录对应关系：**

| 阶段 | 源码路径 |
|------|----------|
| 前端 | `myCompiler/src/frontend/` |
| IR 构建 | `myCompiler/src/midend/irbuild/` |
| 中端优化 | `myCompiler/src/midend/pass/` |
| 后端 | `myCompiler/src/backend/` |

## 2. 前端

详细设计见 [Frontend.md](./Frontend.md)。

### 2.1 流程

1. **词法/语法分析**：ANTLR4（`SysY.g4`）生成 Parse Tree。
2. **AST 构建**：Visitor 遍历 Parse Tree，生成类型化 AST。
3. **语义分析**：类型检查、多级符号表、作用域、常量折叠与错误报告。

### 2.2 设计要点

- ANTLR4 自动化降低手写解析成本，便于维护文法。
- AST 与语义分析解耦，Visitor 可复用于 IR 生成等扩展。
- 多级嵌套符号表保证作用域正确性；语义阶段完成常量折叠，为中端减负。

## 3. IR 设计与中间代码生成

详细设计见 [IRBuild.md](./IRBuild.md)。

### 3.1 IR 层次

参考 LLVM 风格，面向 SysY 做简化定制：

| 层次 | 说明 |
|------|------|
| **Type** | `i32`/`float`/`void`/`string`、指针、数组、函数类型 |
| **Value / User / Constant** | SSA 值、使用者关系、常量体系 |
| **Instruction** | 算术/比较/内存/控制流/Phi/Call/Cast/Copy 等 |
| **BasicBlock / Function / Module** | CFG、函数、模块与全局量 |

### 3.2 IRBuilder

- 递归遍历 AST，生成模块、函数、基本块与指令。
- 自动维护作用域、变量 SSA、分支/循环处的 Phi 合流。
- 支持多维数组初始化、GEP、库函数与控制流（if/while/break/continue）。

### 3.3 设计要点

- 模块化类型/值/指令体系，便于 Pass 分析与变换。
- 构建期即进入 SSA，降低后续 Mem2Reg 负担。
- 流水线末尾 `LoopGccStyleTransform` 将循环降为 GCC 风格（入口判断 + latch 回边），便于后端 LICM / CSE。

## 4. 中端优化

Pass 细节与完整列表见 [IRPass.md](./IRPass.md)。入口：`createOptimizationPipeline`（`OptimizationPasses.cpp`）。

### 4.1 优化等级

| 等级 | 用途 |
|------|------|
| **O0 / O1 / O17** | 完整中端流水线；**O1** 额外启用 `LoopVersioning`；O17 在内联后等多一轮 DCE |
| **O2** | 仅 DCE + Phi 消除（最小/调试） |
| **O15** | 实验配置（大量 Pass 注释） |
| **O16** | 截断后段（GEP 展开、尾递归、Phi、LICM 等），供后端调试 |

日常评测以 **`-O1`** 为主。

### 4.2 流水线阶段（以 O1 为准）

**A — 预处理与内联前**

`CFGSimplification` → `RecursionNormalization` → `MemoizationV2` → `CSE(块内)` → `RemoveRedundantStore` → `Normalization` → `GlobalScalarPromotion` → `PowDivLoopReduction` → `CompareChainFold` → `HelperReturnAnalysis` → `FunctionInlining` → `LoopNestInteriorSplit`

**B — 数组与循环结构**

`ModLoopReduction` → `AllocaCoalesce` → `ArrayElimination` → `RemoveOnlyWriteArray` → `DCE` → `LoopLinearIterationFold` → `ArrayCopyPropagation` → `LoopSumReduction` → `BasicBlockMerge` → `ConstantFolding`

**C — 循环变换与展开**

`LoopIfGuardHoist` → `LoopNestedBoundTightening` → `BBMerge` → `LoopInductionStrengthReduction` → `CondGuardedAccumulate` → `MatrixStructureAnalysis` → `SkewSymmetricLoopRestrict` → `LoopInterchange` → **`LoopVersioning`(O1)** → `LoopUnrolling` → `CopyChainElimination` → `InstructionCombine` → `ArrayStoreLoadForward`

**D — GEP 与算术归约**

`DCE` / `BBMerge` / `ConstantFolding` → `GEPExpansion` → `ArrayStoreLoadForward` → `CSE` → `AddChainReduction` → `GEPChainFold` → `InstructionCombine` → `DCE`

**E — 收尾与后端准备**

`TailRecursionElimination` → `FunctionInlining(二次)` → `GEPToBitCast` → `PhiElimination` → `AddChainReduction` → `LoopInvariantCodeMotion`(IR) → `ConstantFolding` → `CSE` → `SRFixed` → `RemoveRedundantStore` → `BasicBlockReorder` → `DCE` → `RemoveUnusedGlobalAndFunction` → **`LoopGccStyleTransform`**

### 4.3 中端亮点 Pass

| Pass | 作用 |
|------|------|
| **MemoizationV2** | 对适格递归插入统一缓存表，降低重复子问题开销 |
| **RecursionNormalization** | 递归形态规范化，便于后续记忆化 |
| **CompareChainFold** | 可归约为移位的比较链 → `shl`/`sra` |
| **LoopNestInteriorSplit** | guarded 内核拆为 interior / border |
| **LoopLinearIterationFold** | 迭代不变外层 trip 压 1；线性累加器出口补偿 |
| **ArrayCopyPropagation** | 纯拷贝循环删除与基址传播 |
| **LoopVersioning**（O1） | 循环不变除数版本化，供常数除法强度削弱 |
| **CopyChainElimination** | 冗余拷贝链消除 |
| **SRFixed** | 魔数除法/取模、2 的幂移位等强度削弱 |
| **LoopGccStyleTransform** | LLVM 风格循环 → GCC 风格，对接后端 |

### 4.4 中端设计原则

- **Pass 独立、可插拔**：便于 `-O15`/`-O16` 分段调试与 A/B。
- **语义证明优先于模式名匹配**：如迭代折叠与拷贝传播解耦，分别证明安全性。
- **前后端协同**：Phi 消除 → IR LICM → GCC 风格变换，为后端 `li`/`la` 外提与 CSE 铺路。

### 4.5 RVV 循环向量化（`-rvv`）

编译器可选启用 RISC-V Vector（RVV 1.0）扩展：命令行加 **`-rvv`** 时，`LoopVectorizePass` 在 O0/O1/O17 流水线中插入（O17 在 `LoopInterchange` 后与 `LoopGccStyleTransform` 后各跑一轮）。向量化在 IR 层生成 `vecsetvl` / `vecload` / 向量算术 / 归约等指令，后端 `InstructionSelector` Lowering 为 `vsetvli`、`vle32.v`、`vse32.v`、`vlse32.v`、`vsse32.v`、`vred*.vs`、`vf*.vv` 等。

**启用与评测约定**

| 场景 | 编译选项 | QEMU |
|------|----------|------|
| functional / h_functional | `-rvv`（O0 流水线） | `-cpu rv64,v=true,vlen=128` |
| performance2026 | **`-O17 -rvv`** | 同上 |
| 专项模式样例 | `-O17 -rvv` | `case/rvv_patterns/` |

**识别与变换模式（`LoopVectorizePass` + `MatrixStructureAnalysis`）**

| 模式 | 典型源码形态 | IR / 汇编要点 |
|------|--------------|---------------|
| **Scaled-row 更新** | `C[i][j] = C[i][j]*A[i][k] + B[k][j]`（含 `if (A[i][k]==1) continue`） | 矩阵三重循环最内层 `j`；`vecmul` + `vecadd` / 浮点 `vfmul` + `vfadd`；**减法变体** `B[j][k]-=A[j][i]*B[i][k]`（TRSM，`h-10-*`） |
| **逐元素循环** | 常量/不变填充、`dst[i]=src[i]`、`Y[i]=a*X[i]+Y[i]`、逐元素 `add/mul/div/rem/shift` | `findElementwiseLoop`；支持 1D/2D GEP、列索引 `jIV+offset`、strided load/store；**int32 / float** |
| **数组归约** | `sum+=A[i]`、`sum+=A[i]*A[i]`、`sum+=A[i]*B[i]` | strip-mining + `vredsum` / `vfredosum` |
| **数组 max/min** | `m=max(m,A[i])`（含 phi 归约与 **copy-based if 形态**） | `vredmax` / `vredmin`；copy 链累加器用 **copy 链向量体**（非 phi），避免后端寄存器未初始化 |
| **标量链** | `x+=d; sum+=f(x)`，lane 独立计算 + 归约 | `vid.v` 生成 lane 索引 + lane 内表达式 + `vredsum` |
| **原地拷贝链** | 填 `src` → `memmove` 到 `dst` → 仅读 `dst` 求和 | 匹配 `InPlaceCopyOriginChain` 时 **跳过** 向量化，交给 `CopyChainElimination` 消拷贝 |

**流水线协同要点**

- **前置分析**：`MatrixStructureAnalysisPass` 提供 `scaledRowUpdateNests`、`inPlaceCopyOriginChain` 等；存在有效 **inPlaceCopyOriginChain** 时本轮 `LoopVectorizePass` 整函数跳过（标量拷贝链优化更省）。
- **双轮向量化（`-rvv`）**：首轮在循环 interchange 之后；末轮在 **`LoopGccStyleTransform` 之后**（O0/O1/O17 均启用），以便 copy/phi 归约形态稳定后再识别 array max 等模式。
- **循环不变量**：`isLoopInvariantVal` 递归判定（如 `mul(r,N)` 被 LICM 放进 header 仍视为不变），并 **hoist 到 preheader**，避免删旧循环块后悬垂引用。
- **小循环**：trip 可完全展开（≤20）的循环不向量化，交给 `LoopUnrollingPass`。
- **后端**：向量寄存器独立着色；`vsetvli` 按 SEW=32、m1、ta/ma 生成；浮点归约默认 **有序** `vfredosum.vs`。

**验证与增量 QEMU**

- 全量 RVV 正确性：`./run.sh -qemu-test-rvv`（functional + h_functional + performance2026）。
- 汇编 **SHA256 缓存**（`.cache/qemu_asm/asm_sha256.tsv`）：与上次 PASS 且 hash 一致则跳过传输与 QEMU 运行；`FORCE_QEMU=1` 强制全量重测。
- 专项样例：`tools/rvv_patterns_verify.sh`（`case/rvv_patterns/`，同样支持 hash 增量）。

指令语义与后端枚举详见 [RVV.md](./RVV.md)；Pass 实现见 [IRPass.md](./IRPass.md)「LoopVectorizePass」、`LoopVectorizePass.cpp` / `MatrixStructureAnalysis.cpp`。

## 5. 后端

后端将 IR 转为 RISC-V 汇编，采用多阶段 MIR 流水线。实现入口：`RISCVBuilder::generateRISCVCode`（`RISCVBuilder.cpp`）。

### 5.1 后端整体流水线

```
IR 代码
  → 指令选择 (InstructionSelector)
  → 窥孔优化 1 (FirstPeep)
  → 后端 CSE (BlockLocalCSE) — 第 1 轮
  → 循环不变量外提 (LICM)
  → 后端 CSE (BlockLocalCSE) — 第 2 轮（LICM 后再做 li/la 物化合并）
  → 指令调度 (InstructionScheduler) — 仅无访存/调用的纯算术块
  → 图着色寄存器分配
  → 窥孔优化 2 (SecondPeep)
  → 栈偏移重算
  → 汇编生成 (AssemblyEmitter)
  → RISC-V 汇编
```

### 5.2 RISC-V 数据结构

- **`RISCVModule`**：顶层模块，包含函数与全局变量。
- **`RISCVFunction`**：基本块序列、栈帧、活跃性分析结果。
- **`RISCVBasicBlock`**：指令序列与控制流。
- **`RISCVInstruction`**：R/I/S/B/U/J 型指令与伪指令。
- **`RISCVRegister`**：虚拟寄存器与物理寄存器。
- **`RISCVOperand`**：寄存器、立即数、内存地址、标签。
- **`RISCVGlobalBlock`**：全局数据与常量池。

#### 栈帧布局（RISC-V ABI）

```
高地址 (函数入口时的 sp)
+------------------+ <- sp (函数入口)
| raStackSize      | ← 保存返回地址 ra
+------------------+
| valueStackSize   | ← 局部变量、临时值、alloca、callee-saved
+------------------+
| argStackSize     | ← 为调用其他函数预留的参数空间
+------------------+ <- sp (函数执行中)
低地址
```

### 5.3 指令选择

- 按 IR 指令类型匹配 RISC-V 模板；复杂操作分解为多条基本指令。
- 操作数转为寄存器 / 立即数 / 内存；遵循 RISC-V ABI（参数、调用、返回）。
- 覆盖：算术与逻辑、load/store、分支/跳转/call/ret、浮点与 int↔float 转换等。

### 5.4 窥孔优化

架构：`PeepOptimizationManager` + `PeepPass`。各策略独立成 Pass，对指令返回 `DELETE` 时从块中移除。

| 阶段 | 时机 | 说明 |
|------|------|------|
| **FirstPeep** | 指令选择后、寄存器分配前 | 分支融合、DCE、强度削弱、地址融合等 |
| **SecondPeep** | 寄存器分配后 | 清理冗余 `mv` / 恒等 `addw` |

**FirstPeep 顺序**（`RISCVBuilder::FirstPeep`）：

1. **FoldCompareBranchPass** — `slt` + `bne` 等比较-分支融合。
2. **FoldXorZeroBranchPass** — 消除 `xori rd,rs,0` 后改为对 `rs` 分支。
3. **FoldLoopContinueBranchPass** — 「退出分支 + jal 回边」折为反向比较回边。
4. **DeadCodeEliminationPass**（窥孔版）— 删除无使用、无副作用指令。
5. **RemoveRedundantAddwZeroPass** — 删除 `addw rd, rd, zero` 等恒等截断。
6. **RemoveRedundantJalPass** — 删除多余 `jal`。
7. **StrengthReductionPass** — 2 的幂常数乘法 → 移位。
8. **FoldAdjacentMoveAndAddressPass** — 融合 `li`+`mv`、地址计算 + load/store；函数指令数 >3000 时跳过以保证编译时间。

**SecondPeep 顺序**：

1. **RemoveRedundantAddwZeroPass**
2. **RemoveRedundantMovePass** — `mv rd,rd`、连续覆盖同目标 `mv`、乒乓 `mv` 等。

**已实现但未默认启用：**

- **ImmediatePropagationPass** — `li`+算术合并为 I 型立即数指令。

### 5.5 后端公共子表达式消除（BlockLocalCSE）

**位置**：寄存器分配前；FirstPeep 之后，**LICM 前后各一轮**（`runBlockLocalCSEPass`）。

**作用**：函数级、支配关系驱动的 CSE，消除重复 `li`/`la` 物化与纯算术，减少循环内重复 materialize。

| 类别 | 指令 | 说明 |
|------|------|------|
| **物化 (materialAvail)** | `li`、`la` | 键不含目标寄存器；**copy-init 的 `li` 不参与** |
| **算术 (avail)** | `add/sub/and/or/xor/shift/slti` 等 | **不 CSE `mul/mulw`**（避免误删 stride 链） |

**安全条件：**

- 虚寄存器函数内单定义；重复定义时删 duplicate 并将 use 替换为 canonical。
- 跨块替换要求 duplicate 的所有 use 被 canonical 定义块支配。
- `sp` 被改写时失效依赖 `sp` 的 avail 项。
- **`call` 不清空** avail（与 IR 层 CSE 策略不同）。

LICM 外提 `li`/`la` 后，第二轮 CSE 合并 preheader 与循环内重复物化。

### 5.6 循环不变量代码外提（LICM）

**位置**：FirstPeep 与第一轮 BlockLocalCSE 之后；寄存器分配前。

**作用**：将循环不变的 **`la`** / **`li`** 外提到 preheader，并合并语义等价的地址计算。

**不变量判定（`isLoopInvariant`）：**

- `la`：目标为虚寄存器，操作数为标签。
- `li`：目标为虚寄存器；排除 copy-init 与物理临时寄存器。

**外提安全（`canHoistInvariantInst`）：**

- 目标寄存器在循环块集合内唯一定义。
- 同块内若 `li`/`la` 之后还有指令改写其 `rd`，则不外提。
- 子循环 preheader 上的 `la`：若基址虚寄存器在子循环体内被重定义，则跳过。

**算法流程：**

1. `analyseLoops` — 收集顶层循环。
2. `hoistForLoop` — **先递归子循环**，再处理当前循环；有子循环时只扫 `getBlocksWithoutChildren()`。
3. `collectInvariantsInBlocks` — 收集可外提 `li`/`la` 及紧随的地址使用链。
4. 语义等价合并（`InstructionHash` / `InstructionEqual`）。
5. `insertHoistedInst` — 插入 preheader terminator 之前。
6. `mergeLAReg` — 统一后续操作数到保留的基址寄存器。

效果：将 O(n) 次地址/常数 materialize 降为 O(1)（按循环嵌套）；与 BlockLocalCSE 互补。

### 5.7 指令调度（InstructionScheduler）

**位置**：第二轮 BlockLocalCSE 之后、寄存器分配之前。

**模型**：按功能单元（LOAD_STORE / MUL_DIV / BRANCH / INTEGER / FLOAT）与指令延迟建依赖图，基于就绪时间与关键路径启发式重排，支持双发射可行性判断。

**安全约束（当前启用策略）：**

- 含 **load/store** 或 **call/ecall** 的基本块**整块跳过**（曾因全局调度导致正确性问题）。
- 仅对无访存/调用的纯算术块调度；控制流指令保持在段末。
- 指令数过少（≤2）不调度，避免开销大于收益。

### 5.8 寄存器分配

基于《虎书》图着色，配合 `LivenessInfo` 活跃区间与溢出决策：

1. **BUILD** — 冲突图与移动相关边。
2. **SIMPLIFY** — 移除度数 &lt; K 的节点。
3. **COALESCE** — Briggs 保守合并，减少 `mv`。
4. **FREEZE** — 无法合并时冻结移动边。
5. **SPILL** — 按溢出代价选点，插入 load/store。
6. **SELECT** — 出栈着色并重写溢出。

### 5.9 代码生成

- `.data` 段全局变量与常量；函数序言/尾声建立与恢复栈帧。
- `AssemblyEmitter` 将 MIR 转为汇编文本；解析标签与跳转目标。
- 分配完成后 `reallocOffsetForInstructions` 按最终 callee-saved / 栈布局重算偏移。

### 5.10 后端优化亮点

1. **BlockLocalCSE**：支配树驱动的 `li`/`la` 与算术去重；copy-init 隔离、mul 保守排除、`sp` 版本失效；LICM 前后双轮。
2. **LICM**：外提 `la`/`li` 并合并等价物化；子循环优先、同块 rd 改写检测。
3. **两阶段窥孔**：RA 前分支融合/DCE/强度削弱/地址融合；RA 后清理冗余 `mv`/`addw`。
4. **保守指令调度**：仅纯算术块重排，在 ILP 与正确性之间取舍。
5. **与中端协同**：GCC 风格循环 + Phi 消除后的 IR，使后端更易识别可外提的物化模式。

## 6. 设计亮点总览

| 维度 | 要点 |
|------|------|
| **正确性优先** | 后端调度避开访存块；CSE 对 mul / copy-init 保守；拷贝传播要求 store 值即 load 值 |
| **针对 benchmark 的结构化优化** | 记忆化、卷积 interior/border、矩阵稠密打包、迭代不变折叠、原地拷贝起源消减 |
| **中后端闭环** | IR LICM + GCC 风格变换 ↔ 后端 LICM / BlockLocalCSE |
| **RVV 向量化** | `-rvv` 下矩阵 scaled-row、逐元素、归约、标量链；O0/O1/O17 双轮 LV；汇编 hash 增量 QEMU |
| **工程可调试性** | 多优化等级；`-debug -info` 输出各 Pass；大函数跳过昂贵窥孔 |
