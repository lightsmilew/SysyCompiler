# 设计文档

## 前言

本文档为 2025 年毕昇杯编译大赛参赛队伍 移进规约都队 的编译器设计文档。本编译器面向官方提供的 sysy 语言，以自研 IR 为中间表示（详见 [IRBuild.md](./IRBuild.md)），以 RISC-V 为最终目标代码的体系结构。

---

## 前端部分

前端详细设计见 [前端设计文档](./Frontend.md)。

- **词法/语法分析**：使用 antlr4 生成解析树（parse tree）。
- **AST 构建**：采用 visitor 模式遍历解析树，生成抽象语法树（AST）。
- **语义分析**：包括类型检查、符号表管理、作用域处理、常量折叠等。
- **设计亮点**：自动化语法分析、AST 结构清晰、符号表多级嵌套、错误报告详细，详见前端文档。

---

## 中间代码生成

IR 设计与实现详见 [IRBuild.md](./IRBuild.md) 和 [IRPass.md](./IRPass.md)。

- **IRBuilder**：递归遍历 AST，生成自研 IR，支持表达式、控制流、数组、函数等。
- **优化 Pass**：包括死代码消除、公共子表达式消除、循环线性迭代折叠、数组拷贝传播、循环不变代码外提等，详见 [IRPass.md](./IRPass.md)。
- **设计亮点**：模块化 IR 结构、SSA 支持、丰富的优化管道、调试友好。

---

## 后端部分

后端负责将 IR 转换为目标机器代码（RISC-V 汇编），采用经典多阶段设计。

### 后端整体架构

```
IR 代码
  → 指令选择 (InstructionSelector)
  → 窥孔优化 1 (FirstPeep)
  → 后端 CSE (BlockLocalCSE) — 第 1 轮
  → 循环不变量外提 (LICM)
  → 后端 CSE (BlockLocalCSE) — 第 2 轮（LICM 后再做 li/la 物化合并）
  → 图着色寄存器分配
  → 窥孔优化 2 (SecondPeep)
  → 栈偏移重算
  → 汇编生成 (AssemblyEmitter)
  → RISC-V 汇编
```

实现入口：`RISCVBuilder::generateRISCVCode`（`RISCVBuilder.cpp`）。

### RISC-V 数据结构

- **`RISCVModule`**: 顶层模块，包含所有函数和全局变量。
- **`RISCVFunction`**: 函数单元，包含基本块序列、栈帧信息和活跃性分析结果。
- **`RISCVBasicBlock`**: 基本块，包含指令序列和控制流信息。
- **`RISCVInstruction`**: 指令表示，支持 R/I/S/B/U/J 型指令和伪指令。
- **`RISCVRegister`**: 寄存器抽象，支持虚拟寄存器和物理寄存器。
- **`RISCVOperand`**: 操作数，支持寄存器、立即数、内存地址和标签。
- **`RISCVGlobalBlock`**: 全局数据块，处理全局变量和常量池。

#### 栈帧设计

栈帧采用标准的 RISC-V ABI 布局：

```
高地址 (函数入口时的 sp)
+------------------+ <- sp (函数入口)
| raStackSize      | ← 保存返回地址 ra 寄存器
+------------------+
| valueStackSize   | ← 局部变量、临时值、alloca等
+------------------+
| argStackSize     | ← 为调用其他函数预留的参数空间
+------------------+ <- sp (函数执行中)
低地址
```

### 指令选择

- **模式匹配**: 根据 IR 指令类型选择对应的 RISC-V 指令模板。
- **操作数转换**: 将 IR 操作数转换为 RISC-V 操作数（寄存器/立即数/内存）。
- **复杂指令分解**: 将复杂操作分解为多条基本指令。
- **ABI 遵循**: 确保函数调用、参数传递符合 RISC-V ABI 规范。

主要处理的指令类型：

- 算术运算（add, sub, mul, div 等）
- 逻辑运算（and, or, xor, shift 等）
- 内存访问（load, store）
- 控制流（branch, jump, call, ret）
- 浮点运算（fadd, fsub, fmul, fdiv 等）
- 类型转换（int↔float）

### 窥孔优化

窥孔优化（Peephole Optimization）在基本块内滑动窗口扫描指令序列，识别并删除/合并冗余模式。采用 **`PeepOptimizationManager` + `PeepPass`** 的可扩展架构：每个策略独立成 Pass，按序对每条指令调用 `optimize()`，返回 `DELETE` 时从块中移除该指令。

#### 执行时机

| 阶段 | 时机 | Pass 列表 |
|------|------|-----------|
| **FirstPeep** | 指令选择后、寄存器分配前 | 见下表 |
| **SecondPeep** | 寄存器分配后 | `RemoveRedundantAddwZero`、`RemoveRedundantMove` |

**FirstPeep Pass 顺序**（`RISCVBuilder::FirstPeep`）：

1. **FoldCompareBranchPass** — 比较 + 条件分支融合（如 `slt` + `bne` → 单条分支）。
2. **FoldXorZeroBranchPass** — 消除 `xori rd,rs,0` + 分支，改为直接对 `rs` 分支。
3. **FoldLoopContinueBranchPass** — 「退出分支 + jal 回边」折叠为反向比较回边，删除多余 `jal`。
4. **DeadCodeEliminationPass**（窥孔版）— 删除无使用、无副作用的指令。
5. **RemoveRedundantAddwZeroPass** — 删除 `addw rd, rd, zero` 等恒等截断。
6. **RemoveRedundantJalPass** — 删除多余 `jal`。
7. **StrengthReductionPass** — 常数乘法转移位（2 的幂）。
8. **FoldAdjacentMoveAndAddressPass** — 融合 `li`+`mv`、地址计算 + load/store；函数指令数 >3000 时自动跳过（防止超大块耗时）。

**SecondPeep Pass 顺序**（`RISCVBuilder::SecondPeep`）：

1. **RemoveRedundantAddwZeroPass** — 寄存器分配后再次清理恒等 `addw`。
2. **RemoveRedundantMovePass** — 删除 `mv rd,rd`、连续覆盖的同目标 `mv`、乒乓 `mv` 等冗余移动。

#### 已实现但未默认启用的窥孔 Pass

- **ImmediatePropagationPass** — 立即数传播，将 `li`+算术 合并为 I 型立即数指令。

### 后端公共子表达式消除（BlockLocalCSE）

**位置**：寄存器分配前，**FirstPeep 之后、LICM 前后各运行一轮**（`runBlockLocalCSEPass`）。

**作用**：在函数级、基于支配关系的 CSE，消除重复的 `li`/`la` 物化及纯算术表达式，减少循环内重复 materialize。

#### 两类可用表达式

| 类别 | 指令 | 说明 |
|------|------|------|
| **物化 (materialAvail)** | `li`、`la` | 键不含目标寄存器，按立即数或全局标签匹配；**copy-init 的 `li` 不参与**（带 `copyInit` 标记） |
| **算术 (avail)** | `add/sub/and/or/xor/shift/slti` 等 | 按 opcode + 操作数键匹配；**不 CSE `mul/mulw`**（避免误删 stride 链上的偏移计算） |

#### 安全条件

- 虚拟寄存器在函数内**单定义**；重复定义时删除 duplicate 并将 use 替换为 canonical 定义。
- 跨基本块替换时，要求 duplicate 的所有 use 被 canonical 定义块**支配**。
- `sp` 版本号：栈指针被改写时失效所有依赖 `sp` 的 avail 项。
- **`call` 不清空** avail 表（与 IR 层 CSE 策略不同）。

#### 与 LICM 的协作

LICM 外提 `li`/`la` 后，第二轮 CSE 合并 preheader 与循环内重复的物化指令，避免外提引入的冗余 load-immediate / load-address。

---

### 循环不变量代码外提（LICM）

**位置**：FirstPeep 之后、第一轮 BlockLocalCSE 之后；**寄存器分配前**。

**作用**：将循环内每次迭代结果相同的 **`la`（全局/标签地址）** 与 **`li`（循环不变立即数）** 外提到循环 preheader，并合并语义等价的地址计算。

#### 不变量判定（`isLoopInvariant`）

- **`la`**：目标为虚拟寄存器，操作数为标签。
- **`li`**：目标为虚拟寄存器，操作数为立即数；**排除 copy-init 的 `li`**；**排除物理临时寄存器**（假定 load 后立即使用，不可外提）。

#### 外提安全（`canHoistInvariantInst`）

- 目标寄存器在循环块集合内**唯一一次定义**（`isOnlyDefOfDestInBlocks`）。
- 同基本块内，`li`/`la` 之后若还有指令改写其 `rd`（如 `la t2,a; add t2,t2,off`），则**不外提**。
- 子循环 preheader 上的 `la`：若基址虚拟寄存器在**子循环体内**被重新定义，则跳过。

#### 算法流程

1. **`analyseLoops`** — 收集所有顶层循环（`RISCVLoop`）。
2. **`hoistForLoop`** — **先递归处理子循环**，再处理当前循环；无子循环时扫描全部 loop blocks，有子循环时扫描 `getBlocksWithoutChildren()`，避免重复外提内层体。
3. **`collectInvariantsInBlocks`** — 从循环体删除可外提的 `li`/`la`；对 `la` 收集紧随其后的地址使用链（`ADD`/`ADDI`/load/store/`mv`）供寄存器合并。
4. **语义等价合并** — `InstructionHash` / `InstructionEqual`：对 `la`/`li` 按标签/立即数（及 `la` 的 rd 键）合并，忽略不同目标虚拟寄存器差异。
5. **`insertHoistedInst`** — 插入 preheader  terminator 之前。
6. **`mergeLAReg`** — 将合并组内后续指令的操作数统一指向保留的 `la` 基址寄存器。

#### 优化效果

- 将 O(n) 次地址/常数 materialize 降为 O(1)（per loop nest）。
- 支持嵌套循环；子循环 preheader 与父循环 preheader 分工外提。
- 与 BlockLocalCSE 配合：外提后再 CSE，进一步去重。

### 寄存器分配

- **活跃性分析**：`LivenessInfo`类提供精确的活跃区间、def-use 链、冲突检测、溢出决策等。
- **图着色算法**：基于《虎书》的经典算法，包含以下阶段：

1. **BUILD**: 构建冲突图和移动指令图

   - 活跃性分析计算寄存器生命周期
   - 构建寄存器冲突关系
   - 识别可合并的移动指令

2. **SIMPLIFY**: 简化低度数节点

   - 移除度数小于 K 的节点（K 为可用寄存器数）
   - 将节点压入栈中

3. **COALESCE**: 合并移动相关的寄存器

   - Briggs 保守合并策略避免增加着色复杂度
   - 减少不必要的移动指令

4. **FREEZE**: 冻结移动指令

   - 当无法继续合并时，放弃部分移动指令的合并

5. **SPILL**: 处理溢出

   - 选择溢出代价最小的寄存器
   - 生成 load/store 指令访问内存

6. **SELECT**: 实际着色
   - 从栈中弹出节点并分配颜色
   - 处理溢出寄存器的重写，自动插入 load/store 指令，保证正确性。

### 代码生成

- **全局数据段**: 生成 .data 段的全局变量和常量。
- **函数序言/尾声**: 生成栈帧建立与恢复代码。
- **指令序列**: 将 RISC-V 指令转换为汇编文本。
- **符号解析**: 处理标签和跳转目标。

### 后端优化亮点

1. **BlockLocalCSE（后端 CSE）**
   - 支配树驱动的 `li`/`la` 物化与算术表达式去重
   - copy-init `li` 隔离、mul 保守排除、`sp` 版本失效
   - LICM 前后双轮运行，与外提互补

2. **循环不变量代码外提（LICM）**
   - 外提 `la` 与循环不变 `li`；合并语义等价物化
   - 子循环优先、父循环 `BlocksWithoutChildren` 扫描
   - 同块 rd 改写检测与子循环 preheader 特殊规则

3. **窥孔优化（两阶段）**
   - FirstPeep：分支融合、DCE、强度削弱、地址融合等（RA 前）
   - SecondPeep：冗余 `mv` / `addw` 清理（RA 后）
   - 大函数自动跳过地址融合，保证编译时间
