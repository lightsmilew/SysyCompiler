# 扩展文法与中端改造指南

本文按**修改类型**分开写：每种扩展都是一套完整步骤（文法 → 重生成 → AST → Visitor → 语义 → IR → Pass → 后端 → 验证），互不混写。做哪一种就只看对应章节。

---

## 公共准备（所有类型共用）

### 工具与路径

| 路径 | 作用 |
|------|------|
| `antlr-4.13.2-complete.jar`（仓库根） | ANTLR **生成器** |
| `myCompiler/3rd_party/antlr4-runtime/` | C++ **运行时**（链接用，不能生成代码） |
| `myCompiler/src/SysY.g4` | 手写文法 |
| `myCompiler/src/frontend/generate/` | 生成物（勿手改） |
| `frontend/ASTNode.*` / `ASTNodeVisitor.*` / `SemanticAnalysis.*` | 前端手写 |
| `midend/irbuild/IRDataStructure.*` / `IRBuilder.*` | IR |
| `midend/pass/`、`backend/InstructionSelector.cpp` | Pass / 后端 |

### 当前语言能力（改之前）

无 `for`、无 `<<`/`>>`、无 `double`、无 `unsigned`、无源语言指针。IR 已有 `Sll`/`Sra`、`PointerType`（给数组/全局用）。

### 重生成前端（每种改完 g4 后都执行）

改完 `SysY.g4` 后必须重跑 ANTLR，再编译。

#### 方式 A：WSL 里用 **Windows JDK**（推荐，本仓库常用）

WSL 的 `java` 若不可用或版本不对，直接调 Windows 的 `java.exe`。**关键点**：`-jar` / `-o` / 文法文件都要用 **Windows 盘符路径**（`wslpath -w`），否则生成物可能写到错误目录，或 `SysYLexer` 未更新却看似成功。

```bash
# 仓库根目录：/mnt/d/work/compiler/SysY
REPO=/mnt/d/work/compiler/SysY
# 按本机实际 JDK 路径调整（示例为 jdk-17）
JAVA_WIN="/mnt/c/Program Files/Java/jdk-17/bin/java.exe"

WIN_JAR=$(wslpath -w "$REPO/antlr-4.13.2-complete.jar")
WIN_OUT=$(wslpath -w "$REPO/myCompiler/src/frontend/generate")
WIN_G4=$(wslpath -w "$REPO/myCompiler/src/SysY.g4")

"$JAVA_WIN" -jar "$WIN_JAR" \
  -Dlanguage=Cpp \
  -no-listener \
  -visitor \
  -o "$WIN_OUT" \
  "$WIN_G4"

# 确认生成成功（应能 grep 到你新增的 visitXxx / 词法名）
# grep -n 'visitYourNewRule\|YourNewToken' \
#   myCompiler/src/frontend/generate/SysYBaseVisitor.h \
#   myCompiler/src/frontend/generate/SysYLexer.h

cd "$REPO"
./run.sh -rebuild
```

也可写成一行函数，放进 shell 配置或脚本：

```bash
regen_antlr() {
  local REPO="${1:-/mnt/d/work/compiler/SysY}"
  local JAVA_WIN="${JAVA_WIN:-/mnt/c/Program Files/Java/jdk-17/bin/java.exe}"
  "$JAVA_WIN" -jar "$(wslpath -w "$REPO/antlr-4.13.2-complete.jar")" \
    -Dlanguage=Cpp -no-listener -visitor \
    -o "$(wslpath -w "$REPO/myCompiler/src/frontend/generate")" \
    "$(wslpath -w "$REPO/myCompiler/src/SysY.g4")"
}
```

#### 方式 B：WSL / Linux 原生 `java`

若已安装可用的 JDK 11+：

```bash
cd /mnt/d/work/compiler/SysY/myCompiler/src

java -jar ../../antlr-4.13.2-complete.jar \
  -Dlanguage=Cpp \
  -no-listener \
  -visitor \
  -o frontend/generate \
  SysY.g4

cd /mnt/d/work/compiler/SysY
./run.sh -rebuild
```

#### 注意

- 新 `#label` 必须在手写 `ASTNodeVisitor` 里实现对应 `visitXxx`；关键字写在 `Ident` **之前**。
- 词法里多字符算符（如 `+=`、`++`）应放在单字符（`+`）**之前**，或依赖 ANTLR 最长匹配；字符字面量等规则的字符集写法要合法（例如 `~[\\'\r\n]`，错误转义会导致规则进不了 Lexer、只剩 Parser 隐式 token）。
- 生成后看 `frontend/generate/` 的时间戳与 `SysYLexer.h` / `SysYBaseVisitor.h` 是否包含新符号；不要只依赖命令退出码。

### 推荐实施顺序

1. 移位 → 2. for → 3. unsigned → 4. 指针 MVP → 5. double

## 类型一：增加 `for` 循环

目标：`for (init; cond; step) stmt;`，`continue` 进 **step**，`break` 出循环。建议脱糖为 while，减少 Pass 改动。

### 步骤 1 — 改 `SysY.g4`

词法区（`Ident` 前）加：

```antlr
FOR: 'for';
```

`stmt` 增加一臂，并增加辅助规则：

```antlr
stmt
    : ...
    | WHILE LPAREN cond RPAREN stmt           #whileStmt
    | FOR LPAREN forInit? SEMICOLON cond? SEMICOLON forStep? RPAREN stmt  #forStmt
    | BREAK SEMICOLON                         #breakStmt
    | ...
    ;

forInit
    : bType varDef (COMMA varDef)*   #forInitDecl
    | lVal ASSIGN exp                #forInitAssign
    ;

forStep
    : lVal ASSIGN exp                #forStepAssign
    | exp                            #forStepExpr
    ;
```

### 步骤 2 — 重生成 ANTLR

执行上文「重生成前端」命令。确认 `SysYBaseVisitor.h` 出现 `visitForStmt`、`visitForInitDecl` 等。

### 步骤 3 — AST

`ASTNode.h` 新增：

```cpp
class ForStmtNode : public StmtNode {
public:
  shared_ptr<StmtNode> init;       // Decl / Assign / nullptr
  shared_ptr<ExprNode> condition;  // nullptr = true
  shared_ptr<StmtNode> step;
  shared_ptr<StmtNode> body;
};
```

在 `ASTNode.cpp` 补 `toString` / `print`。

### 步骤 4 — Visitor

实现：

- `visitForStmt`
- `visitForInitDecl` / `visitForInitAssign`
- `visitForStepAssign` / `visitForStepExpr`

组装成 `ForStmtNode`。

### 步骤 5 — 语义分析

在 `SemanticAnalysis`：

1. `visitForStmt`：`Push` 作用域 → 分析 init → cond → body → step → `Pop`
2. for 体内 `loopDepth++`（与 while 相同，保证 break/continue 合法）
3. init 里声明的变量不能泄漏到 for 外

### 步骤 6 — IRBuilder

对照 `visitWhileStmt`，实现 `visitForStmt`（或 Visitor 阶段脱糖成 `Block + While`，IR 只认 while）。

若直接建 CFG：

```text
PushVarsStack
生成 init
建 cond / body / step / exit
br cond
cond: 条件；空则 br body；否则 condbr body, exit
body: loopStack.push(step, exit)；visit body；无 terminator 则 br step
step: visit step；br cond；补 phi
exit: 补 phi；PopVarsStack
```

要点：`continue` → **step**；`findBlockVariantVars` 扫 **body+step**。

### 步骤 7 — 中端 Pass

脱糖成 while 后：**一般不用改 Pass**。若自建 for CFG，确认循环 Pass 能认出 header/回边。

### 步骤 8 — 后端

无新指令，**跳过**。

### 步骤 9 — 验证

```c
int main() {
  int s = 0;
  for (int i = 0; i < 10; i = i + 1) {
    if (i == 5) continue;
    if (i == 8) break;
    s = s + i;
  }
  return s; // 23
}
```

检查 IR：`continue` 是否进 step 块。

## 类型二：支持移位 `<<` `>>`

目标：源码移位；有符号 `>>` 用算术右移。IR 已有 `Sll`/`Sra`，后端已支持。

### 步骤 1 — 改 `SysY.g4`

词法（放在 `LT`/`GT` 附近，独立 token）：

```antlr
SHL: '<<';
SHR: '>>';
```

在 `addExp` 与 `relExp` 之间插入 `shiftExp`，并改 `relExp`：

```antlr
shiftExp
    : addExp                         #toAddExp_shift
    | shiftExp (SHL | SHR) addExp    #shiftOpExp
    ;

relExp
    : shiftExp                       #toShiftExp_rel
    | relExp (LT | GT | LE | GE) shiftExp #relOpExp
    ;
```

可选：`constExp: shiftExp;`（允许常量移位）；否则保持 `constExp: addExp`。

优先级：`mul → add → shift → rel → eq → land → lor`。

### 步骤 2 — 重生成 ANTLR

执行公共重生成命令。注意：原 `#toAddExp_rel` 若改名为 `#toShiftExp_rel`，旧 `visitToAddExp_rel` 必须改名或删除。

### 步骤 3 — AST

`BinaryOp` 增加 `Shl`、`Shr`；`toString(BinaryOp)` 同步。

### 步骤 4 — Visitor

实现：

- `visitShiftOpExp` → `BinaryExprNode(..., Shl/Shr)`
- `visitToAddExp_shift` → 透传
- `visitToShiftExp_rel` → 透传（若改了 label）

### 步骤 5 — 语义分析

1. 操作数必须是 `INT`（浮点移位报错）
2. 常量折叠：`<<`、算术 `>>`
3. `getExprType`：结果为 `INT`

### 步骤 6 — IRBuilder

`createBinaryOp`：

```cpp
case BinaryOp::Shl: opcode = Opcode::Sll; break;
case BinaryOp::Shr: opcode = Opcode::Sra; break; // 有符号
```

常量折叠分支同样加上。

### 步骤 7 — 中端 Pass

- `ConstantFoldingPass`：补 `Sll`/`Sra` 折叠（建议做）
- `CompareChainFold` / `SRFixed`：已会生成移位，一般兼容
- 其余可暂不动

### 步骤 8 — 后端

只做有符号移位：**不用改**。  
（若以后 unsigned 的 `>>` 要逻辑右移，再加 `Opcode::Srl` + selector，见类型四。）

### 步骤 9 — 验证

```c
int main() {
  int a = 1 << 3;   // 8
  int b = -8 >> 2;  // -2
  return a + b;
}
```

检查 IR/汇编为 `sll`/`sra`，不是 mul/div。

## 类型三：增加 `double`

目标：源码 `double` 类型与运算。工作量大；完整路线要动 IR + 后端。也可先「语法接受、降为 float」占位。

下面按**完整支持**写步骤。

### 步骤 1 — 改 `SysY.g4`

```antlr
bType
    : INT          #typeInt
    | FLOAT        #typeFloat
    | DOUBLE       #typeDouble
    ;

DOUBLE: 'double';
```

字面量建议：保留 `1.0` 为 float，增加 `1.0d` 为 double（改 `FloatConst` 或另加 `DoubleConst`）。`funcType` 经 `bType` 自动支持返回 `double`。

### 步骤 2 — 重生成 ANTLR

执行公共命令。确认出现 `visitTypeDouble`。

### 步骤 3 — AST

```cpp
enum class PrimaryDataType { INT, FLOAT, DOUBLE, STRING, VOID };
```

可选：`DoubleLiteralExprNode`，或 float 字面量带精度标记。所有 `switch (baseType)` / `toString` 补 `DOUBLE` 分支。

### 步骤 4 — Visitor

`visitTypeDouble` → `PrimaryDataType::DOUBLE`；字面量规则按你选的后缀策略解析。

### 步骤 5 — 语义分析

1. 提升：`int+float→float`，`int/float+double→double`
2. 赋值：`double←int/float` 允许；`float←double` 允许（可警告）
3. `getExprType` / 常量折叠覆盖 double
4. 库函数：可选 `getdouble`/`putdouble`，或暂不支持

### 步骤 6 — IR 类型与 Opcode（`IRDataStructure`）

1. 增加 `DoubleTyID`、`DoubleType`（`toString` → `"double"`）
2. 增加 `ConstantDouble`
3. 算术：推荐独立 `DAdd/DSub/DMul/DDiv`、`DCmp`；转换 `FPExt`/`FPTrunc`，以及与 int 的 `SIToFP`/`FPToSI`
4. `getOpcodeName` / `clone` / `isBinaryOp` 同步
5. 全局变量构造：`isIntegerTy() || isFloatTy()` 处加上 `isDoubleTy()`
6. 辅助：`isFPTy(t) = isFloatTy || isDoubleTy`

### 步骤 7 — IRBuilder

1. `bType → Type*`：`DOUBLE` → `DoubleType`
2. 二元/比较：double 走 `D*`
3. 隐式 cast：int/float/double 两两
4. Alloca/Load/Store：按 8 字节

### 步骤 8 — 中端 Pass

凡写死「只有 float」处复查：

| 动作 | Pass |
|------|------|
| 折叠 double | `ConstantFoldingPass` |
| 勿混 float/double CSE | `CSEPass` / InstCombine |
| 第一阶段直接 skip | `LoopVectorizePass`（现 SEW=32） |

建议：先保证标量正确，向量化暂禁 double。

### 步骤 9 — 后端（必做）

1. `InstructionSelector`：`fadd.d`/`fsub.d`/`fmul.d`/`fdiv.d`、比较、`fld`/`fsd`
2. spill 槽 8 字节；ABI 传 double
3. 数据段 `.double`

### 步骤 10 — 验证

```c
double add(double a, double b) { return a + b; }
int main() {
  double x = 1.5d;
  double y = add(x, 2.25d);
  return 0;
}
```

确认汇编是 `*.d` / `fld`，不是 `*.s` / `flw`。

## 类型四：增加 `unsigned` 类型

目标：`unsigned int`；影响 `/` `%` 比较 `>>`。推荐 IR 仍用 `i32`，用 `UDiv`/`URem`/`Srl`/无符号 icmp 区分。

### 步骤 1 — 改 `SysY.g4`

```antlr
bType
    : INT                 #typeInt
    | UNSIGNED INT        #typeUInt
    | FLOAT               #typeFloat
    ;

UNSIGNED: 'unsigned';
```

（`UNSIGNED` 写在 `Ident` 前。）可选：`IntConst` 增加 `u`/`U` 后缀。

### 步骤 2 — 重生成 ANTLR

确认 `visitTypeUInt`。

### 步骤 3 — AST

```cpp
enum class PrimaryDataType { INT, UINT, FLOAT, STRING, VOID };
```

所有类型 `switch` / 打印补 `UINT`。

### 步骤 4 — Visitor

`visitTypeUInt` → `PrimaryDataType::UINT`；字面量后缀（若有）解析为 unsigned。

### 步骤 5 — 语义分析

1. 混合运算：简化为「有一边 UINT → 结果 UINT」
2. 比较：统一符号性后再比
3. 若已有移位：`UINT` 的 `>>` 为**逻辑**右移；`INT` 为算术右移
4. 数组下标：接受 `INT`/`UINT`
5. 符号表条目携带完整 `DataType`（含 UINT）

### 步骤 6 — IR Opcode（`IRDataStructure`）

新增（若没有）：

- `Opcode::UDiv`、`URem`、`Srl`
- `ICmp` 谓词：`ULT/ULE/UGT/UGE`

同步 `getOpcodeName` / `clone` / `isBinaryOp`。  
**不要**新建整型单例类型（太重）；值仍是 `i32`。

### 步骤 7 — IRBuilder

1. 声明/参数：`UINT` → `IntegerType`，但根据表达式符号性选指令
2. `/` `%`：有符号 `SDiv`/`SRem`，无符号 `UDiv`/`URem`
3. 关系运算：选 `slt` 系或 `ult` 系
4. `>>`：有符号 `Sra`，无符号 `Srl`
5. 常量折叠用对应无符号语义

### 步骤 8 — 中端 Pass

| Pass | 动作 |
|------|------|
| `SRFixedPass` | `UDiv` 单独路径或暂不优化 |
| `ConstantFolding` | 无符号折叠 |
| `ValueRangeAnalysis` | unsigned 区间 `[0, UINT_MAX]` |
| 循环 IV | 保守：可不优化 unsigned 归纳变量 |

### 步骤 9 — 后端

1. `divu`/`remu`（或 `divuw`/`remuw`）
2. `srl`/`srliw`
3. 无符号分支/比较：`bltu`/`bgeu` 等

### 步骤 10 — 验证

```c
int main() {
  unsigned int a = 1u << 31;
  unsigned int b = a >> 31;  // 1（逻辑右移）
  unsigned int c = 5u / 2u;  // 2
  return (int)(b + c);       // 3
}
```

对照：有符号 `1<<31 >> 31` 应为 `-1`。

## 类型五：支持指针

目标 MVP：`int *p`、`&x`、`*p`、指针赋值、数组名退化；可选 `p+i` / `p[i]`。  
IR 已有 `PointerType`/`GEP`/`Load`/`Store`；缺的是源语法与「取址变量」地址模型。

### 步骤 1 — 定 MVP 范围

先做：声明、取址、解引用读写、`p=&x`、`p=a`。  
暂缓：函数指针、`void*`、复杂 cast、`malloc`。

### 步骤 2 — 改 `SysY.g4`

词法（`AND` 已是 `&&`，取址必须新 token）：

```antlr
AMP: '&';
```

声明带星：

```antlr
varDef: stars Ident (LBRACKET constExp RBRACKET)* (ASSIGN initVal)?;
constDef: stars Ident (LBRACKET constExp RBRACKET)* ASSIGN constInitVal;
stars: MUL*;

funcFParam:
      bType stars Ident                                              # scalarParam
    | bType stars Ident LBRACKET RBRACKET (LBRACKET constExp RBRACKET)* # arrayParamNoSize
    | bType stars Ident LBRACKET constExp RBRACKET (LBRACKET constExp RBRACKET)* # arrayParamWithSize
    ;
```

（若改 `funcFParam`，注意与现有 `#scalarParam` 等 label 对齐，避免 Visitor 全挂。）

一元取址/解引用：

```antlr
unaryExp
    : primaryExp                       #toPrimaryExp
    | Ident LPAREN funcRParams? RPAREN #callExp
    | unaryOp unaryExp                 #opUnaryExp
    | AMP unaryExp                     #addrOfExp
    | MUL unaryExp                     #derefExp
    ;
```

赋值左值支持 `*p`：

```antlr
lVal
    : Ident (LBRACKET exp RBRACKET)*   #idLVal
    | MUL unaryExp                     #derefLVal
    ;
```

（给 `lVal` 加 label 后，原 `visitLVal` 可能要拆成两个 visit。）

### 步骤 3 — 重生成 ANTLR

确认 `visitAddrOfExp`、`visitDerefExp`、`visitDerefLVal` 等。

### 步骤 4 — AST

`DataType` 增加指针层数：

```cpp
struct DataType {
  PrimaryDataType baseType;
  vector<shared_ptr<ExprNode>> arrayIndices;
  int pointerLevel = 0; // 0 非指针，1 = T*，…
  bool _isConstVariable = false;
};
```

表达式：

```cpp
class AddrOfExprNode : public ExprNode { shared_ptr<ExprNode> operand; };
class DerefExprNode  : public ExprNode { shared_ptr<ExprNode> operand; };
```

或扩展 `UnaryOp { AddrOf, Deref }`。声明节点写入 `pointerLevel`。

### 步骤 5 — Visitor

1. `stars` 计数 → `DataType.pointerLevel`
2. `visitAddrOfExp` / `visitDerefExp` / `visitDerefLVal`
3. 赋值左部为 deref 时正确建 `AssignStmtNode`

### 步骤 6 — 语义分析

1. `&`：操作数必须是左值
2. `*`：操作数 `pointerLevel>=1`；结果层数 -1
3. 指针赋值类型兼容；数组名 → 首元素指针
4. 可选：`p+i` 类型仍为指针
5. **预扫 `AddrOf`**：标记符号 `needsAddress`（供 IR 用）

### 步骤 7 — IRBuilder（核心）

| 源 | IR |
|----|-----|
| 取址变量 / 全部局部（二选一模型） | `alloca`，读写 `load`/`store` |
| `&x` | 取 alloca/全局地址 |
| `*p` 读 | `load` |
| `*p=v` | `store` |
| `p+i` | `GEP` |
| 数组名 | 已有退化 |

地址模型二选一：

- **P1**：所有局部都 `alloca`（简单，优化变差，或后续 Mem2Reg）
- **P2**：仅 `needsAddress` 的变量 `alloca`，其余仍 SSA（推荐 MVP）

### 步骤 8 — 中端 Pass

有指针参数或 address-taken 时：

- 保守关闭/限制激进 `ArrayElimination` 等
- `GEP` 相关 Pass 可能受益
- 无别名分析时，经指针的 load/store 优化一律保守

### 步骤 9 — 后端

一般已有指针 lowering。检查 RV64 地址宽度、`i32*`/`float*` 的 GEP 步长。

### 步骤 10 — 验证

```c
int main() {
  int x = 3;
  int *p = &x;
  *p = 4;
  return x; // 4
}
```

```c
int main() {
  int a[3] = {1, 2, 3};
  int *p = a;
  return *(p + 2); // 3
}
```

## 附录 B：for 与 while 的 CFG

while：`continue → cond`。  
for：`continue → step → cond`。  
`loopStack.continueBlock = step` 即可复用现有 break/continue 生成。
